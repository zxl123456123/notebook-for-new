# 开发路线图与阶段验收

状态：目标后端仍待实现；2026-11-25。阶段是交付顺序，不是工期承诺；没有真实内容量、团队投入和部署约束，不虚构完成日期。当前已有设计文档与 `work/` 下本地预览，预览不代表完成 Phase 1 的数据库、权限与部署验收；总体架构确认要求沿用原方案。

## Phase 0：调研和可审查设计

交付五份互相链接的文档：总体架构、技术选型、模块设计、数据模型、路线图。调研包含至少三套可落地组合，解释维护状态、许可证、后台体验、部署和长期扩展取舍。提供系统图、依赖图、实体关系、权限矩阵及 AI 接口边界。

验收：所有推荐都有官方资料或仓库依据；区分实时核验信息、设计建议与尚未验证能力；无业务代码和服务部署。核对五份文件存在、内部链接有效、状态和实体名称一致，审查公开/私有、发布、附件、地图和 AI 的权限链路。不能把文档结构检查当成实际系统安全测试。

**阶段出口：用户确认总体方案。** 如有异议先修改方案，不以默认栈替代确认。授权后的最小验证集中在版本兼容、中文搜索、Markdown 编辑和权限，失败时在小范围重新选型。

## Phase 1：可运行的基础网站

按以下顺序实施，每步保持可以验证的交付。首期重点是读者找到指南、编辑者更新内容、管理员审核发布。

| 切片 | 内容 | 验收证据 |
| --- | --- | --- |
| 1A 基础运行 | 锁定兼容版本；Next.js、Payload、Postgres；环境校验；基础迁移；README 和本地启动 | 全新环境启动、生产构建、迁移到空库；版本和命令有记录 |
| 1B 权限与资源 | 登录、邀请/受控开户、角色、草稿/发布、公开/组内；上传及受控下载 | 访客/成员/编辑者/管理员矩阵集成测试；直连 API 和附件不能绕过 |
| 1C 指南闭环 | Markdown 编辑预览、树形导航、培养阶段、目录锚点、附件、关联链接；标题/正文搜索 | 非技术成员独立完成建稿、预览、提交发布；中文关键词和完整正文可查；空结果有反馈 |
| 1D 门户与视觉 | 首页、研究方向独立页、成员（含已授权的基础校友名录）、成果、新闻的基础展示与后台；统一布局和组件 | 桌面与手机实机/浏览器检查；样例数据明确标识，可由后台换成真实内容 |
| 1E 可部署交付 | Compose、生产迁移、备份恢复、错误日志、CI 的类型/构建/必要测试 | 普通服务器部署演练；空环境恢复数据库与附件；失败和限制记录入报告 |

基础分类、标签字段在 Phase 1 建模，但复杂筛选和治理不抢先实现。门户新闻纳入基础内容模型与展示，避免首页只能写死动态。基础关联推荐为编辑者维护的相关文章，不引入算法推荐。

材料归档并入现有切片：1C 增加每周组会的多项汇报、论文 PDF/幻灯片及分类资料；1D 增加按活动持续补图的相册。用户按[目录交接约定](data-model.md#材料交接与增量导入)提供材料，本地预览展示适配结果；后续 Payload 适配器才负责稳定 ID、路径对账、去重报告与版本持久化，不能把选择文件或浏览器内预览当成后台导入。模块归属见[模块设计](module-design.md#边界与依赖)。

归档验收使用真实材料样本：无封面的 PDF/PPT/PPTX 能直接归入日期文件夹，已有多汇报人目录仍可浏览；同一资料主题下的文档和网站链接可定位；相同活动追加照片而不重复建相册；重复扫描不增副本，改名/移动可对账，内容变更保留旧文件，歧义进入 issues。所有导入默认内部草稿；逐张照片公开授权及撤回、直接文件 URL 权限由后端集成测试确认。1E 恢复演练同时覆盖数据库、私有持久卷和导入映射，不仅检查目录存在。

Phase 1 的必要测试覆盖：匿名不可读取内部正文、草稿或私有附件；成员不能发布；编辑者不能更改角色或越权发布；修改公开为内部后旧链接与缓存失效；非法 Markdown/上传不能执行脚本；直接访问和搜索具有相同权限结果。用真实边界行为测试，不为每个展示组件写镜像式测试。

阅读验收覆盖 360px 手机、平板及桌面宽度，无整页横向滚动；表格/代码允许容器内滚动。键盘能完成导航、搜索和登录，焦点可见，地图/AI尚未上线时不存在死入口。自动无障碍检查结合人工检查，记录未解决问题。

性能建议目标：在明确记录设备和网络条件下，主入口 LCP ≤2.5s、CLS ≤0.1；现场数据不足时仅报告实验室测量，不宣称已满足真实用户指标。中文搜索按架构文档的固定评测集建立基线，记录 p95、数据量、并发和失败题。

阶段出口：指南及门户可由后台维护，真实权限和附件测试通过，生产构建及恢复演练有证据。团队验收内容流程后才扩大功能范围。

## Phase 2：校友地图与内容发现

交付世界/中国地图视图、城市聚合、校友公开卡片、年份/行业/升学就业筛选、等价列表；后台维护去向、地理数据和公开授权。校友授权记录与撤回操作优先于地图装饰。

完善文档分类、标签、多维筛选、相关内容和后台编辑体验。高级搜索不是强制新增引擎：先评测数据库方案，只有召回或延迟达到架构中的切换条件才试点 Meilisearch，并对比同一批问题。

验收必须包括：

- 世界和中国视图对同一批数据得到一致结果，聚合数与筛选列表一致；多人同城不会相互遮挡到无法访问。
- 未授权、撤回授权和内部个人字段不出现在 API、GeoJSON、弹窗、计数或搜索；用网络响应独立核查，不能只看页面。
- 地理位置只使用授权精度；底图、字体、瓦片来源与许可已记录，中国底图实际访问、坐标匹配和适用要求已核查。
- 地图加载失败、无 WebGL、手机和键盘情况下仍可通过列表找到公开校友；所有筛选状态可清除。
- 如启用外部搜索，撤回内容即使索引滞后也不能泄露；重建索引可恢复相同结果，运维有备份和同步故障处置说明。

阶段出口：真实授权样本验证通过，内容负责人能够维护和撤回资料；功能开关关闭地图时指南与门户正常工作。

## 首页问答试点

2026-11-26 更新。首页和档案的桌面浏览已可本地体验，下一轮可以先做 Phase 3A 的只读导航试点。地图、完整 CMS 和向量检索可以按原计划推进。组内账号与受控下载是对成员开放真实材料的前提，本机原型可以先用公开内容和隔离的测试材料验证。

首页保留课题组介绍，在「学生专栏」和「组内档案」旁提供「问问组里」入口。点开后在当前页提问，短答下方直接给可打开的笔记章节或文件。推荐问题来自已收录内容。已有主页专栏锚点可用，档案还需能定位单场组会，当前预览文件链接也会随改名而改变。

| 学生的问题 | 第一版应交付的结果 |
| --- | --- |
| 上次组会谁讲了什么，讲解 PPT 在哪？ | 从日期、汇报人和文件目录定位相应场次，逐项列出实际附件。只收录论文时说明「这场组会只查到 PDF」。同名或多场命中时给出日期供选择。 |
| 第一次汇报怎么准备？有没有模板？ | 引到经组里确认的指南段落和可用模板。能找到阅读建议、找不到模板时分别说明。 |
| 论文里这个算法比基线快多少？ | 仅有目录时给出原件。以后由负责人选入正文检索的材料，才凭可定位的原文片段回答，数字要能在对应页找到。 |

归档与问答共用一份来源。日常放入 PDF、PPT、照片即可完成归档。目录检索只读日期、标题、已有汇报人和文件类型。指南的已发布文字经许可可用于回答，示例数据与活动照片均排除在问答知识源之外。

### 开源架构取舍

| 参考 | 在本项目中的用法 |
| --- | --- |
| OpenClaw | 用独立的 Docker 实例运行问答，网站后端在私网调用 Gateway。共享令牌具有操作者权限，学生的浏览器只连接本站。站点后端提供本轮可读的材料，实例禁用命令、文件、消息、跨会话和外网抓取等工具，独立于管理员的个人助手。上线前要验证有效工具清单。 [官方仓库](https://github.com/openclaw/openclaw) · [HTTP 接口](https://docs.openclaw.ai/gateway/openai-http-api) · [信任边界](https://docs.openclaw.ai/gateway/security) |
| Haystack | 借鉴先按元数据缩小检索范围、再把答案引用对应回输入文档的做法。在当前网站内实现这两个步骤，首版无须运行额外的 Python 检索服务。 [官方仓库](https://github.com/deepset-ai/haystack) · [元数据过滤](https://docs.haystack.deepset.ai/docs/metadata-filtering) · [引用解析](https://docs.haystack.deepset.ai/docs/answerbuilder) |
| Onyx | 其连接器适合多来源知识的持续同步。当前来源只有站内指南和档案目录，引入整个平台会额外维护一份索引与权限映射。其连接器的源权限同步也有版本限制。 [官方仓库](https://github.com/onyx-dot-app/onyx) · [连接器说明](https://docs.onyx.app/overview/core_features/connectors) |

第一个可验收的版本应让学生从首页问出一个问题，打开正确原件，再用一个尚未收录的问题验证缺失提示。文件导航可由目录直接返回。需要组织自然语言回答时，已有的 `/api/assistant/query` 接口设计负责服务端授权和检索，再把获准的最少证据交给 OpenClaw，最后核对引用并生成站内链接。模型不可用时仍可打开检索结果。保留原有门户单体，Gateway 作为其私网依赖。

本机预览服务没有组员身份，各条目录也沿用路径标识。给全组开放前，需要落地成员登录、来源和附件鉴权、稳定引用，并由内容负责人确认可供外部模型处理的范围。首批使用逐次独立请求，在同一张测试表中用两个身份验证不可越权、资料撤回后不可再引用。模型、额度和云机实测留到接入阶段，成员资料和聊天记录均不进入共享记忆。

## Phase 3：权限感知的 AI 助手

首页试点验证后，再按真实问题加入 RAG。采用统一提供商接口，检索只返回当前用户可访问的已发布内容。首批覆盖指南和档案元数据，后续按篇选择允许检索正文的附件。

| 顺序 | 实施范围 | 验收 |
| --- | --- | --- |
| 3A 导航 | 聊天入口、受控检索、站内链接、超时及限流 | 导航到正确文档；模型不可用时可继续普通搜索 |
| 3B 有引用问答 | 文档分段、版本及锚点、索引更新/删除、引用回查 | 每条事实性回答能追溯来源；无依据明确说明不足 |
| 3C 权限与质量 | 身份隔离、撤权即时复核、提示注入评测、提供商切换、成本统计 | 匿名与成员问同题只见各自允许内容；更换提供商不修改页面 |

建议建立不少于 50 题的评测集，包含正常问答、无答案、过期版本、私有文档、恶意文档指令及跨用户会话。通过标准至少包含零已知越权泄露、引用指向正确可访问版本；引用支持率、答题正确率和成本阈值由团队基于试点结果确认。所有数字是待执行计划，不是已有测试结果。

上线前确认内部资料外发规则、模型服务协议及费用上限；只向提供商发送最小必要片段，日志不默认保存私密原文。写入、发布、发邮件、执行科研工具等高影响工具另立需求及审批流程，不随只读助手上线。

阶段出口：AI 关闭或故障时主体网站独立可用，索引可以重建，内容撤回和身份变更测试通过，责任人接受质量与费用边界。

## Phase 4：按真实需求扩展

由团队实际使用提出下一个模块，如模板管理、设备资源或科研工具箱。每次只新增一个明确业务能力，先确认数据归属、角色、路由、迁移和公开接口；不能以“未来平台”为理由先建设通用流程引擎。

用一次小模块接入检验扩展成本：新增模块目录、静态注册、路由薄壳、迁移和测试，不要求改动多个现有模块的内部逻辑。记录修改点数及原因；若核心装配散落，先修正边界再扩展。

运行时插件或服务拆分仅在独立部署需求、不可信执行或经测量的资源瓶颈出现时评审。到时单独定义插件清单版本、兼容范围、安装/升级/停用/卸载、数据保留、沙箱和权限，而非把当前静态模块称为已具备这些能力。

## 跨阶段交付纪律

每个实施切片有独立变更、实际验证命令、退出码和结果；失败必须保留在报告中，修复后说明复测结果。阶段验收前检查差异、用户操作和部署资料。正式提交遵循 conventional commits；推送发布前核对远端与待推送范围。

需要补充的项目输入：团队名称及品牌资料、首批指南与公开内容、内容负责人、部署地域/域名、身份来源、校友授权样本、预期规模及预算。除总体架构批准是 Phase 1 的明确前置条件，其余在各自依赖阶段收集，不阻塞本轮设计交付。
